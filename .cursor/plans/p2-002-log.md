# P2-002 滚木 `pref_log` + `Log.ts`

## 业务目标

实现滚木唯一主脚本 `Log.ts`，覆盖程序滚动、长度增减、黄线蓄力、蓝线固定/失败淡出、跑酷段流程状态框架，并产出符合 §P0-A 节点结构的 `pref_log` 预制体与 ANIM_MANIFEST §log 空动画 clip。滚木数值全部读取 `GameConfig`，禁止创建 `LogController.ts`。

**澄清结论（用户确认）**：本阶段做完整逻辑框架，先完成滚木自身状态机与接口，不把电锯、加长道具、场景黄蓝线检测系统一并扩展进本任务。

**v2 修订（业务冲突）**：跑酷推动阶段，滚木与玩家**同速前进**；无论玩家左右移动或滚木变长/变短，玩家始终处于滚木**中间位置**推滚木（参考设计图：玩家双手位于滚木长度中点）。原 v1「滚木独立 `logRollSpeed` 前进 + 仅预留联动接口」不满足该需求。

## 风险等级

**中** — 涉及脚本、prefab、动画 clip 新建；**v2 新增 Player↔Log 跑酷推动耦合**（需小幅修改 `Player.ts` 暴露速度/绑定接口）；滚木长度变化须以中心锚点对称伸缩，避免玩家相对位置漂移。

## 实施步骤

### S1: 创建空动画 clip

通过 Cocos CLI `assets-create-asset-by-type`（`ccType: animation-clip`）在 `assets/resources/animations/log/` 创建 `roll.anim`。该 clip 为 ANIM_MANIFEST 规定的空占位资源，`duration = 0.1s`，供 `Animation` 组件挂载，实际滚动由程序驱动。

### S2: 实现 `Log.ts` 与 `Player.ts` 跑酷推动耦合

路径 `assets/scripts/item/Log.ts`，`@ccclass('Log')`，禁止新增 `LogController.ts`。

**节点引用与锚点**

- `@property` 绑定 `visualNode`（Visual 子节点，挂 Animation）
- 根节点使用 `RigidBody2D`，碰撞体保持在 Root（与 §P0-A 一致）
- **中心锚点设计**：滚木 Root 位于几何中点；`extend()` / `shrink()` 以中点对称伸缩 Visual scale 与 Collider 尺寸，确保长度变化时推动点不偏移

**核心状态**

- 至少拆分 `rolling` / `charging` / `fixed` / `failed` 四个阶段
- 维护 `_currentLength`、`_isLocked`、`_isFading`、`_pushPlayer` 等内部状态

**跑酷推动耦合（v2 重点）**

- `bindPlayer(player: Node | null)`：建立/解除推动关系；跑酷段开始时由场景或 `beginParkour()` 调用
- `fixedUpdate`（`rolling` 且已绑定玩家时）：
  1. **同速**：读取玩家当前速度（`Player.getVelocity()` 或玩家 `RigidBody2D.linearVelocity`），滚木 `linearVelocity` 与玩家完全一致
  2. **居中**：滚木 Root 的横向坐标（X）与玩家保持一致，使玩家始终处于滚木长度中点（双手推滚木中部）
  3. **前进**：纵向（道路前进轴，与 `Player.ts` parkour 模式一致）速度取自玩家，**禁止**推动阶段单独使用 `GameConfig.logRollSpeed` 驱动
- `unbindPlayer()` / `finishParkour()`：解除耦合，滚木进入后续黄线/蓝线流程
- 玩家左右移动时，滚木随玩家横向平移；滚木 `extend()` / `shrink()` 后重新 `_refreshLengthVisual()` 但不改变玩家相对滚木中心的偏移

**`Player.ts` 最小改动（同任务内）**

- 新增 `getVelocity(): Readonly<Vec2>` 返回当前 `_velocity`，供 `Log.ts` 读取
- 可选 `bindLog(log: Log | null)` 保存引用；跑酷模式 `fixedUpdate` 逻辑不变（玩家仍控制左右 + 自动前进）
- 推动阶段**不**由滚木反向驱动玩家位置，避免双端互相拉扯；以玩家为运动主控、滚木跟随同速 + 横向对齐

**长度变化**

- `extend()`：按 `GameConfig.logExtendAmount` 增长，受 `logMaxLength` 限制；**中心锚点对称伸缩**
- `shrink()`：按 `GameConfig.logShrinkAmount` 缩短，受 `logMinLength` 限制；同上
- 长度变化后 `_refreshLengthVisual()` 更新碰撞盒与 Visual，玩家仍保持在中点

**黄线 / 蓝线流程接口**

- `enterChargeZone()`：切入 `charging`，降低前进速度（与玩家速度缩放联动）
- `tryLockAtFinish(canLock: boolean)`：`true` → `fixed`；`false` → `failed` 淡出
- 本任务不负责黄线/蓝线碰撞检测

**跑酷段流程接口**

- `beginParkour()` / `finishParkour()`：明确推动开始/结束
- 固定成功后保留刷怪侧事件钩子

### S3: 创建 `pref_log.prefab`

通过 Cocos CLI `assets-create-asset-by-type`（`ccType: prefab`）创建 `assets/resources/prefabs/item/pref_log.prefab`。

**节点层级（§P0-A）**

```
pref_log (Root — 几何中点/推动锚点)
├── 组件: RigidBody2D + Collider2D + Log.ts
└── Visual (子节点)
    ├── Sprite → default_sprite，anchorY=0，sizeMode=RAW
    ├── Animation → 挂 `roll`
    ├── Billboard → visualNode 指向自身
    └── SortingOrder2D → visualNode 指向自身
```

- 初始长度以中点对称向两侧（或沿道路轴前后）延伸；玩家在 Root 对应中点后方贴合
- **禁止**手写或改 `.meta` uuid

### S4: Prefab 自检与资源刷新

- 执行资源刷新，确保 prefab / script / clip 正常关联
- 手测：玩家左右移动、滚木 extend/shrink 后，玩家仍位于滚木中点，且前进速度一致
